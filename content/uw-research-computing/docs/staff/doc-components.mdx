The standard components the guides use, in alphabetical order, each with one example and how
it renders. A guide uses them by name, with no import. A tag that is neither standard nor
imported fails `npx tsx scripts/check-docs.mts` with `unknown component`. For how guides are
written more generally, see
[Writing documentation](/uw-research-computing/staff/writing-documentation/).

Leave a blank line after every opening tag and before every closing tag, as in the examples;
otherwise the Markdown inside is treated as inline text.

## Built on MUI

These components are built from [MUI](https://mui.com/material-ui/all-components/) (Material
UI) components, styled with the site's theme, so `primary` is CHTC red. When none of the
components here fit, a guide can import an MUI component directly. Each component's MUI page
lists its options; spacing and colors can be adjusted with the
[`sx` prop](https://mui.com/system/getting-started/the-sx-prop/).

```markdown
import Alert from '@mui/material/Alert';

<Alert severity="info">

Maintenance is scheduled for Tuesday morning.

</Alert>
```

## Adding your own component

A component used in a single guide can live anywhere in the repository; import it at the top
of the guide by its path, like any other. One that several guides will use belongs in the
standard set:

1. Create `app/uw-research-computing/_components/<Name>.tsx`:

   ```tsx
   import type { ReactNode } from 'react';
   import { Box } from '@mui/material';

   /** A gray panel. */
   const Panel = ({ children }: { children: ReactNode }) => (
     <Box sx={{ bgcolor: 'grey.100', p: 2, borderRadius: 1, my: 2 }}>{children}</Box>
   );

   export default Panel;
   ```

   It is a server component, rendered once when the site is built. A component that reacts to
   clicks or keeps state needs `'use client';` as its first line.
2. Add it to the map in `app/uw-research-computing/_components/docComponents.tsx`: import it
   at the top, then list it with the others at the end of `docComponents()`:

   ```tsx
   import Panel from './Panel';
   // …
       UpcomingEvents,
       Panel,
     };
   ```
3. Use it in any guide by name:

   ```markdown
   <Panel>

   Markdown inside works as usual.

   </Panel>
   ```
4. Add a section for it to this page, with an example.

## Column

One column. Put it in [`Columns`](#columns).

- `accent`: a red rule down the left side.
- `width`: a fixed share of the row, such as `"30%"`. Without it the columns share the row
  equally.
- `align="center"`: center the column's contents.

Used in [Get help](/uw-research-computing/get-help/).

```markdown
<Columns>

<Column width="30%">

A narrow column on the left.

</Column>

<Column accent>

A wider column with the red rule.

</Column>

</Columns>
```

## ExcerptTabs

One tab per guide whose frontmatter sets the flag, in file order. Each tab shows that guide's
excerpt: everything above a `{/* more */}` line, or its first paragraph.

- `flag` (required): `software_icon` (the software guides) or `basic_scripting` (the
  basic-scripting guides). The tab's label is the guide's `software` field, or its `title`.
- `more`: add a "More information" link to each guide.

Used in [How to Use Software](/uw-research-computing/software-overview-htc/) and
[Basic Scripting and Job Submission](/uw-research-computing/htc-basic-scripting/).

```markdown
<ExcerptTabs flag="basic_scripting" />
```

Log in with your NetID, not your full email address.

</Tip>

## UpcomingEvents

The next events with a tag, from the events repository. Shows nothing when none are coming up.

- `tag`: only events with this tag. Without it, all events.
- `limit`: how many to show, in braces because it is a number: `limit={2}`. Defaults to 2.

Used in [Bioinformatics Café](/uw-research-computing/bioinformatics-cafe/).

```markdown
<UpcomingEvents tag="bioinformatics-cafe" limit={2} />
```
