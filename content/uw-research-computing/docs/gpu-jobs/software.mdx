# Software Environment 

Using a GPU to accelerate your code requires using software and packages that were designed to take advantage of GPU hardware. Popular machine learning frameworks (e.g., PyTorch, JAX, TensorFlow), programming languages (e.g., Julia via CUDA.jl, C++ via CUDA), data science libraries (e.g., RAPIDS, CuPy), and scientific computing applications (e.g., COMSOL, GROMACS, OpenFOAM, LAMMPS) provide dedicated GPU packages. Many of these tools also have CPU-only versions, so ensure you install the GPU-enabled versions. We provide some example [GPU jobs and workflows on CHTC in GitHub](https://github.com/CHTC/templates-GPUs).

We recommend your script verifies it is running on a GPU, as some packages will fall back on CPUs when a GPU is not found, which can cause your script to run very slowly or not at all. The command `nvidia-smi` may not be available within your container, so instead verify within using a method within your software or to check the version of your software. For example, with PyTorch:

  ```python3
  import torch
  print(torch.cuda.is_available())
  ```

## Use a container (recommended!)

We recommend that you use a Docker or Apptainer container to install your software environment. A container is somewhat like a virtual operating system where you can install software and run your code. Your jobs will bring a container with it and run your code in it, enabling you to run your software on any computer without having to install your software's dependencies on each computer for each job. Additionally, containers are frozen, making them great for reproducibility. 

Many developers publish base Docker container images that come pre-installed with everything needed to run on a GPU on [Docker Hub](https://hub.docker.com/). For security, you should generally look for pre-made official images from a verified publisher. NVIDIA also publishes [containers optimized for its GPUs](https://catalog.ngc.nvidia.com/?topTech=container). 

To install your own software into a pre-made container, follow our guides on building containers with [Apptainer on CHTC servers](uw-research-computing/apptainer-build/) or with [Docker on your own computer](uw-research-computing/docker-build/). You can also come to office hours to work with a facilitator to build a container. Our [GitHub](https://github.com/CHTC/templates-GPUs/tree/master/containers) has some recipes for GPU containers.

## Compiled code

You can use our usual methods of creating a portable installation of a software package (as in our R and Python guides) to run on GPUs. Most of our build servers and GPU servers have copies of the CUDA runtime that you can use to compile code. To get onto one of these servers, submit an interactive job, following the instructions in our [interactive job guide](/uw-research-computing/inter-submit/), or submit a GPU job submit file with the interactive flag for `condor_submit`. Once on a build or GPU server, see which CUDA versions are available by looking at the path `/usr/local/cuda-*`.

We strongly recommend software installation strategies that include the CUDA runtime in the final installed code, so that jobs can run on servers even if a different version of the CUDA runtime is installed (or there is no runtime at all). For compiled code, look for flags that enable static linking, or use a container.

# GPU architectures, software development kits, and drivers

All of the GPUs hosted on CHTC are made by NVIDIA. NVIDIA develops the CUDA platform for software to communicate with a GPU, which includes the software development kit CUDA toolkit. A CUDA toolkit version requires a driver that can run it. Drivers are backwards compatible but not always forwards compatible without additional software, meaning that a driver has a maximum CUDA toolkit version it can support. Additionally, new chip generations may drop support for old CUDA versions, effectively giving a window of compatibility for CUDA version, drivers, and GPU generation. This can be confusing to match and can create hard-to-diagnose errors when a mismatch occurs. We have tested every major version of the machine learning frameworks PyTorch, JAX, and TensorFlow against the GPUs and drivers in our pool. To see what version of CUDA you should install in your software environment for maximum compatibility with our system based on the framework you are using, please see our [GPU compatibility tool](/uw-research-computing/gpu-jobs/gpu-compatibility).
