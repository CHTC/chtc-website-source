CHTC's HTC system is primarily meant for submitting batches of large workloads. However, a few GPUs are set aside for testing and troubleshooting GPU jobs interactively.

# Availability

## Open capacity GPUs 

We have *dedicated* slots for interactive jobs on CHTC's open capacity GPU machines:

| Number of slots | GPU model | Number of GPUs per slot | GPU Memory |
| --- | --- | --- | --- |
| 4 | NVIDIA GeForce RTX 2080 Ti | 1 | 10.6 GB |
| 1 | NVIDIA A100 | 1 | 39.5 GB |

The slots in the table above *only* run interactive GPU jobs and are primarily intended for testing and troubleshooting. Interactive GPU jobs can still run on other slots on shared GPU machines (including both open capacity and backfill slots), but will wait in the queue with non-interactive jobs.

**All interactive GPU jobs have a maximum runtime of 4 hours.**

You will not be able to run `condor_ssh_to_job` on non-interactive GPU jobs, as this option has been disabled on shared GPUs due to misuse. You can still check in on the output of your jobs while they are running by using `condor_tail` (see [here](/uw-research-computing/htc-monitor-jobs/) for more details).

## Researcher-owned GPUs

If you have access to researcher-owned GPU machines, you may submit interactive jobs within those machines' resource limits. `condor_ssh_to_job` is permitted on these machines.

# Submit an interactive GPU job

1. Ensure your resource requirements allow you to match to an interactive GPU slot.
1. Submit your job with the `-i` command.
    

   <Terminal>
   ```
   condor_submit -i <submit_file>
   ```
   </Terminal>

1. When your job starts, you will see a welcome message and your prompt will change, for example:


   <Terminal>

   ```
   Waiting for job to start...
   Welcome to slot1_1@gpulab2001.chtc.wisc.edu!
   == NOTICE: THIS NODE IS ON PUPPET ENVIRONMENT "puppet8" ==

   [netid@gpulab2001 scratch]$
   ```

   </Terminal>

1. When you are done with your interactive session, type `exit` to return back to the Access Point.
